# 专业花盆助手设计

**日期：** 2026-07-24  
**状态：** 待用户审阅

## 目标

将 DeepSeek 接口约束为智能植物养护与本项目设备诊断助手，不再作为通用聊天机器人；同时将“分析当前环境”从一句简短建议升级为基于实时数据的结构化养护报告。

## 行为边界

允许的主题：植物养护、浇水、土壤、光照、温湿度、传感器读数、OLED、蜂鸣器、继电器、水泵、ESP32 智能花盆使用与故障排查。

无关主题（如编程基础、写作、娱乐、数学等）由本地后端直接拒绝，不调用 DeepSeek。返回文本说明助手仅处理花盆养护与设备状态问题，并提示用户可以询问的内容。

## 处理流程

```text
用户消息
  -> 本地主题过滤
  -> 无关：固定拒答，不调用 DeepSeek
  -> 相关：附带实时设备状态和专业系统提示词，调用 DeepSeek
```

## 输出规则

### 当前环境分析

接口仍为 `POST /api/ai/advice`，但要求回答固定包含四个部分：

1. 数据解读：引用温度、湿度、光照、土壤 ADC、告警和水泵状态。
2. 风险判断：指出低光、温湿度异常或土壤数据未标定等情况。
3. 建议操作：给出可执行且保守的植物养护动作。
4. 注意事项：明确本系统自动浇水关闭，土壤 ADC 未标定时不得根据 ADC 自动决定浇水。

### 花盆相关问答

回答使用分点形式，解释判断原因和推荐操作。回答应专业完整但避免泛泛长文。

### 水泵安全

AI 只提供建议，不直接触发水泵。涉及浇水时只能提示使用网页手动浇水；最终执行仍由 ESP32 本地轮询和 3 秒超时保护决定。

## 实现边界

- 修改 `ai_client.py`，增加主题判定函数与更详细的系统提示词构造。
- 修改 `app.py`，在聊天接口调用 DeepSeek 前执行主题过滤；环境分析使用结构化报告请求。
- 新增单元测试，覆盖相关/无关主题、拒答不调用模型、环境分析请求文本与既有离线错误行为。
- 不改动 `.env`、DeepSeek 密钥、网页结构、ESP32 草图或硬件接线。

## 验证标准

1. 发送“我想学习 Python 基础知识”时，返回花盆助手范围说明，且模型调用函数不被执行。
2. 发送“现在需要浇水吗？”时，模型收到当前传感器状态并返回专业回答。
3. 点击“分析当前环境”时，结果包含数据解读、风险判断、建议操作和注意事项。
4. 现有 11 项后端测试继续通过，新增过滤与结构化输出测试通过。
