# ESP32 Wi-Fi 桥接设计

**日期：** 2026-07-24  
**状态：** 待用户审阅

## 目标

让 ESP32-S3 接入手机 2.4GHz 热点“智能花盆”，自动向运行在电脑 `10.220.151.30:8000` 的后端上报状态，并获取网页下发的手动浇水命令。电脑、手机和 ESP32 已连接至同一热点。

本阶段只新增无线桥接能力，不修改已经完成实机验证的正式总程序集，也不启用自动浇水。

## 方案比较

1. **独立 Wi-Fi 桥接测试草图（采用）**：先在独立目录中复用现有传感器、蜂鸣器和水泵安全控制逻辑，验证联网后再合入正式固件。风险最小，出现问题容易定位。
2. 直接修改正式总程序集：文件少，但任何联网问题都可能影响当前可演示版本，不采用。
3. 由电脑读取串口后代为上报：无需 ESP32 联网，但不是独立物联网设备，不符合本项目演示目标，不采用。

## 组件与职责

### 私密连接配置

`wifi_secrets.h` 只保存在用户电脑本地，包含热点名称、热点密码、后端 IP 与端口。该文件加入忽略规则，不复制到文档、不发送到聊天、不写入正式草图。

### ESP32 桥接测试草图

新建 `wifi_bridge_test/`：

- 初始化时连接 2.4GHz 热点；连接失败不影响本地传感器采集、OLED、蜂鸣器、串口命令和水泵超时保护。
- 每 5 秒调用 `POST /api/device/report`，上报温度、湿度、光照、土壤 ADC、告警和水泵状态。
- 每 1 秒调用 `GET /api/device/command`；仅识别 `water` 和 `stop`。
- `water` 调用现有的受 3 秒最长运行时间限制的启动函数；`stop` 调用已有停止函数。网络命令不得绕过本地安全保护。
- Wi-Fi 断开或后端不可达时，串口输出简洁状态并周期性重连；不得使用长时间阻塞等待。
- 保留串口 `W`、`S`、`H` 命令，便于答辩现场本地控制。

### 电脑后端

现有后端保持不变，运行命令：

```powershell
python -m backend.ai_assistant.app --host 0.0.0.0 --port 8000
```

后端以 15 秒未收到上报判断设备离线。5 秒上报周期能够避免状态过期。

## 数据流

```text
ESP32 采集状态
  -> HTTP POST http://10.220.151.30:8000/api/device/report
  -> 后端保存最新数据
  -> 手机/电脑网页显示状态，DeepSeek 基于最新数据提供建议

网页“手动浇水/停止”
  -> 后端命令队列
  -> ESP32 HTTP GET /api/device/command
  -> 本地 startPump()/stopPump() 与 3 秒保护
```

## 安全与边界

- 仅限可信的手机热点局域网，不做公网映射。
- Wi-Fi 密码和 DeepSeek 密钥均不进入源码、文档、串口日志或聊天记录。
- 土壤 ADC 当前未完成干湿标定，自动浇水继续禁用。
- 后端离线、Wi-Fi 断开、传感器异常时，不得自行启动水泵。
- 网络控制只增加一条受保护的手动浇水入口，不改变继电器、水泵供电或接线。

## 验证标准

1. 使用 `arduino-cli compile --fqbn esp32:esp32:esp32s3` 编译通过。
2. 烧录后串口显示已获得 IP 或明确的重连状态。
3. 网页持续显示“设备在线”，并至少连续 30 秒刷新数据而不离线。
4. 手机网页下发“浇水”后，ESP32 在 1 秒内轮询到命令，水泵启动且最多运行 3 秒；下发“停止”后水泵立即停止。
5. 关闭热点或停止后端后，ESP32 本地采样、告警、串口控制和水泵超时保护仍然正常。

## 不包含的内容

- 自动浇水策略
- 公网部署、账号认证或远程穿透
- DeepSeek 密钥配置变更
- 变更既有硬件接线
