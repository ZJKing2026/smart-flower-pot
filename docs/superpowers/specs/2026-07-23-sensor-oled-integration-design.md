# 多传感器与 OLED 第一阶段集成设计

日期：2026-07-23

## 目标

在一个独立 Arduino 草图中同时读取 SHT30、GY-30/BH1750 和电容式土壤湿度传感器，并通过 SH1106 OLED 与串口每2秒显示一次数据。本阶段只验证采集和显示链路，不执行报警与浇水控制。

## 文件边界

- 新建：`sensor_oled_integration_test/sensor_oled_integration_test.ino`。
- 保留各独立硬件测试草图不变。
- 旧的 `step2_sensor_test/` 只作为历史参考，不直接修改或复用其中未经验证的报警、LED、水泵及土壤百分比逻辑。

## 硬件与引脚

- I²C SDA：`GPIO8`。
- I²C SCL：`GPIO9`。
- I²C 时钟：`100000 Hz`。
- SHT30 地址：`0x44`。
- GY-30/BH1750 地址：`0x23`。
- SH1106 OLED 地址：`0x3C`。
- 土壤湿度模拟输出：`GPIO1`。
- 串口波特率：`115200`。

SHT30、BH1750 和 OLED 共用 I²C 总线，电源与地保持现有已验证接线。

## 数据采集

### SHT30

- 每轮读取温度和相对湿度。
- 温度有效范围为 `-40～125°C`。
- 相对湿度有效范围为 `0～100%`。
- 读到 `NaN` 或超范围值时，本轮温湿度标记为无效。

### BH1750

- 使用连续高分辨率模式。
- 每轮读取光照强度，单位为 `lx`。
- `NaN` 或负数标记为无效。

### 土壤湿度传感器

- ADC 分辨率为12位，GPIO1 使用 `ADC_11db` 衰减。
- 每轮连续采样20次，每次间隔5毫秒，取平均值。
- 仅显示原始 ADC 平均值，不计算湿度百分比。
- 原始值超出 `0～4095` 不可能由正常12位ADC产生；若后续出现固定0或4095，则作为接线或传感器异常进行排查，但本阶段不触发蜂鸣器。

## 初始化与容错

- 初始化顺序：串口、I²C、OLED、SHT30、BH1750、ADC。
- OLED 初始化后显示简短启动页面。
- SHT30 和 BH1750 分别保存初始化状态。
- 任一传感器初始化或读取失败时，不阻塞其他传感器和 OLED 刷新。
- 无效数据在 OLED 上显示 `--`，串口输出对应错误状态。
- 本阶段不使用动态内存分配，不保存历史曲线。

## OLED 显示

OLED 使用 SH1106 128×64 全缓冲模式和英文字体，每2秒刷新，显示四行：

```text
Temp:  27.3 C
Hum:   54.0 %
Light: 205 lx
Soil:  3284 ADC
```

当某项无效时对应数值显示 `--`。不显示未经真实土壤标定的百分比。

## 串口输出

每轮输出采样编号及四项数据。有效值输出单位，无效值输出明确的 `invalid` 或初始化失败信息，便于判断故障所在模块。

## 刷新节奏

- 完成一次传感器读取、串口输出和 OLED 刷新后等待2秒。
- 土壤20次采样额外耗时约100毫秒，可接受。
- 本阶段使用阻塞延时，后续加入报警、浇水和网络任务时再改为基于 `millis()` 的非阻塞调度。

## 安全边界

- 蜂鸣器 GPIO11 保持未使用状态。
- 继电器 GPIO10 不在本草图中配置，水泵不连接负载测试。
- 不加入阈值报警、土壤百分比、滞回控制、自动浇水、WiFi 或云平台逻辑。

## 验证标准

1. Arduino CLI 使用 `esp32:esp32:esp32s3` 编译通过。
2. 启动时串口显示 OLED、SHT30、BH1750 的初始化状态。
3. OLED 和串口每2秒同步显示温度、湿度、光照和土壤ADC。
4. 手遮挡光照传感器时光照值明显下降，移开后恢复。
5. 接近或轻触 SHT30 时温湿度读数产生合理变化并恢复。
6. 触碰土壤传感器探头时 ADC 值按此前独立测试规律变化。
7. 运行至少2分钟，无死机、OLED停刷或I²C设备丢失。
