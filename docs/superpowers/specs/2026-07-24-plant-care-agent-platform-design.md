# 植物养护 Agent 平台设计

**日期：** 2026-07-24  
**状态：** 待用户审阅

## 定位

构建独立的植物养护 AI Agent 平台。智能花盆只是平台的第一个物联网接入设备，为 Agent 提供实时环境数据和受保护的手动浇水入口。平台同时可回答不依赖设备的植物选购、品种推荐、光照、浇水、换盆、施肥、病虫害初步排查等问题。

## 第一版范围

1. 植物问答：面向全流程植物养护问题的流式对话。
2. 本地 RAG 知识库：以 Markdown 文档保存可审核的植物和设备知识。
3. 智能花盆接入：读取现有 ESP32 状态，执行现有受保护手动浇水命令。

第一版不包含账号登录、多用户隔离、图片识别、自动浇水、云端数据库或公网部署。

## 系统架构

```text
独立 Agent Web UI
  -> Agent API
      -> 意图路由
      -> RAG 关键词检索
      -> DeepSeek API（流式生成）
      -> 结果缓存
  -> 花盆适配接口
      -> 现有设备状态/命令 API
      -> ESP32 本地 3 秒保护
```

## API-first 设计

- Agent 平台独立运行，对外使用 `/api/v1/` 前缀；智能花盆只是第一个客户端。
- `POST /api/v1/agent/chat`：接收 `question` 与可选 `deviceContext`，返回回答文本、意图和引用来源。
- `GET /api/v1/knowledge`：返回知识库文档元数据。
- `POST /api/v1/agent/analyze-device`：接收设备状态或读取花盆状态适配器，生成结构化环境分析。
- `GET /api/v1/health`：返回服务与知识库状态，便于其它项目接入检测。
- 花盆已有 `/api/device/status`、`/api/device/command` 保持不变。

## RAG 知识库

初版采用本地 Markdown 和中文关键词检索，不引入向量数据库。

- `knowledge/plants/`：植物选购、光照、浇水、换盆、施肥、病虫害资料。
- `knowledge/devices/`：传感器、继电器、水泵、土壤 ADC 标定与安全规则。
- 每篇文档有标题、标签和正文；后端按关键词和标签评分，取前 3 个片段给模型。
- 回答附带引用文档标题，便于答辩展示知识依据。

## 意图路由

意图包括：`plant_recommendation`、`daily_care`、`disease_check`、`device_diagnosis`、`device_environment`、`out_of_scope`。

本地规则只拦截明确无关内容；植物名称、品种购买、俗称和自然表达默认放行给 RAG 与 DeepSeek，避免“多肉推荐”被关键词漏掉。模型系统提示词要求对不属于植物养护的问题简短说明边界。

## 性能与交互

- 为相同问题、相同设备状态建立短时缓存。
- RAG 只传入前三个相关片段，控制提示词长度。
- DeepSeek 使用流式响应，网页逐段显示内容。
- 系统提示词要求纯文本标题和项目符号，不输出 Markdown `**` 或 `*`；前端按文本行渲染，避免排版与注入风险。

## UI

桌面端采用植物工作台布局：左侧导航（问答、知识库、智能花盆、API 中心），中间为对话/分析区域，右侧为设备实时状态。移动端改为单列卡片。

界面使用深绿、米白与浅叶绿配色；回答使用固定卡片、清晰标题、编号步骤和来源标签。流式生成时显示“正在分析”状态。API 中心展示端点、请求字段和不含密钥的调用示例。

## 安全边界

- RAG 文档与回答不得包含或输出 API Key、Wi-Fi 密码。
- Agent 只建议，不直接控制水泵。
- 涉及浇水时，智能花盆仍以 ESP32 本地最长 3 秒保护为准。
- 土壤 ADC 未完成真实干湿标定前，Agent 不得建议自动浇水。

## 验证标准

1. “我想买个多肉，有什么推荐？”进入植物推荐流程并返回 RAG 来源。
2. “我想学习 C 语言”返回范围说明，不调用 RAG/DeepSeek。
3. 花盆环境分析能引用实时数据并保留浇水安全限制。
4. 同一问题短时重复提问命中缓存。
5. 网页流式显示不出现 Markdown 星号，移动端排版可读。
